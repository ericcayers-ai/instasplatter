## Summary

The renderer literature has decisively moved from "sort everything, then blend" to two families: (a) **per-pixel/tile-local sorting** (StopThePop, gsplat, FlashGS) and (b) **sorting-free stochastic or atomic visibility** (Gaussian Point Splatting, StochasticSplats, 64-bit/vec2u depth buffers). Both families are **compute-shader designs**, and standard WebGL2 (GLSL ES 3.00) has no compute shaders, no atomics, no image load/store and no 64-bit integers — so the sorting-free frontier is WebGPU-only, and InstaSplat's WebGL2 path is architecturally capped near the 8–16M-splat regime that `GaussianSplats3D` documents for CPU sorting.

The commercially usable, immediately actionable material is (1) **streaming/LOD container formats** (`splat-transform` Streamed SOG, MIT; SPZ, MIT; 3D Tiles 2.0 + `KHR_gaussian_splatting`), which is what actually solves "100M+ splats in a browser", and (2) **WGSL building blocks** (`nff747/splat-bvh-core` Apache-2.0 radix-sort + LBVH) plus MIT anti-aliasing (`Analytic-Splatting`) that can be dropped into a WebGPU backend. Several of the strongest quality references (CityGaussian, Horizon-GS, Urban-GS, LoDOfGaussians, hierarchical-3d-gaussians, Scaffold-GS, Octree-GS, EAGLES, LightGaussian, Speedy-Splat, SplatSuRe, taming-3dgs, mip-splatting, 3DGS-MCMC) return **`NOASSERTION`** from the GitHub API — i.e. no recognized SPDX license — so they are concept references, not vendorable code.

## What this means for a WebGL2 + WGSL port

**1. The "sorting-free" frontier is not reachable from WebGL2 at all.** WebGL2 is GLSL ES 3.00: no compute shaders, no atomic operations, no image load/store, and no 64-bit integer types (Khronos WebGL 2.0 spec). Every 2024–2026 popping fix in section A depends on one of those features — StopThePop needs per-pixel lists, Gaussian Point Splatting and StochasticSplats need atomic depth/visibility writes, `splat-bvh-core` needs compute. **Direct evidence:** `mkkellogg/GaussianSplats3D`, the most mature pure-WebGL2 viewer, ships CPU/WASM sorting and documents caps of roughly 8M–16M splats plus crashes on very large scene extents. Our current architecture therefore has a hard ceiling well below the 100M+ goal.

**2. WebGPU has no `atomic<u64>`, so the "64-bit atomic visibility buffer" must be re-specified.** WGSL has no `u64` type; the `shader-int64` feature in native `wgpu` is not a browser feature. WebGPU instead offers the **optional** `atomic-vec2u-min-max` feature (WGSL `atomic<vec2<u32>>` with `atomicStoreMin`/`atomicStoreMax`), which is adapter-dependent and must be feature-detected. Practical consequence for the port: quantise depth into 32 bits (or vec2u min-max where available) with an explicit precision/tie-break policy, and keep a non-atomic fallback path. This is the single most important correction this sweep produces for `src/splat/pointSplatting.ts`.

**3. Buffer limits, not splat counts, dictate the geospatial architecture.** WebGPU's default `maxStorageBufferBindingSize` is 128 MiB (default `maxBufferSize` 256 MiB), so at 32 bytes/splat one binding holds roughly 4.19M splats (2.10M at 64 bytes). 100M+ splats is *necessarily* a chunked, streamed, LOD'd problem — which is why items #50 (Streamed SOG), #55 (3D Tiles 2.0) and #14/#20 (hierarchical chunk layouts) matter more than any rasterizer micro-optimisation. Design the geospatial path around per-chunk storage buffers from day one.

**4. Recommended backend split.** Keep WebGL2 as the universal path and invest there in what actually works: chunk-level frustum + screen-space-error culling, analytic anti-aliasing (#39), filtered EWA (#8), mip 2D filtering (#38), and aggressive attribute quantisation (#45/#46) to raise the effective splat ceiling. Add a **feature-detected WebGPU backend** for the sorting-free path (#2/#11) behind a setting, exactly mirroring the existing Standard/Experimental pattern in `settings.rs`. Do not attempt to emulate atomics on WebGL2 by splitting 64-bit values into two 32-bit words — that is not atomic and produces nondeterministic depth artifacts.

**5. Format strategy is the real win and it is cheap.** Adopt SPZ (already exporting) + SOG/Streamed SOG (#50) as the delivery formats and `KHR_gaussian_splatting` + 3D Tiles 2.0 GLB tiles (#54/#55) as the interchange target. This is MIT/Apache-2.0 all the way, requires no GPU work, and is the only path in this sweep that can be shipped in days rather than weeks.

**6. Licence hygiene.** Of the 59 repos, 17 return `NOASSERTION` and 4 return `null`; several of the most attractive quality references (CityGaussian, Horizon-GS, Urban-GS, LoDOfGaussians, Scaffold-GS, Octree-GS, hierarchical-3d-gaussians, mip-splatting, Speedy-Splat, SplatSuRe, EAGLES, LightGaussian, taming-3dgs, 3DGS-MCMC) fall in that set. Under the repo's existing policy these are **concept references only** until a human reads the LICENSE file. The licence-clean shortlist is: gsplat, VastGaussian, MatrixCity, Grendel-GS, Spark, SuperSplat, GaussianSplats3D, gsplat.js, three.js, PlayCanvas engine, Babylon.js, spz, splat-transform, 3dgs-compression-survey, glTF, CesiumJS, Mini-Splatting2, EAGLES-adjacent quantisation ideas (verify), Analytic-Splatting, StochasticSplats, Gaussian Point Splatting, splat-bvh-core, web-splat, FlashGS, 3DGRUT, SurfelNeRF, DynIBaR, GoDe, Scthe, WebGPU-Splat-Viewer, WebSplatter.

## Method, and evidence limitations (read before trusting a cell)

- **Stars / license / push date:** taken from the GitHub REST response for `api.github.com/repos/<owner>/<name>`. Direct `api.github.com` calls hit the unauthenticated rate limit (60/hr) partway through this sweep (`core.remaining=0`), so the majority of responses were retrieved through the read-only `https://r.jina.ai/https://api.github.com/repos/...` proxy, which returns the same GitHub JSON from a different egress IP. Spot-checks against `img.shields.io/github/license` and `ungh.cc/repos` agreed on every cross-checked repo (spz: 942/MIT; three.js: MIT). **Snapshot is 2026-11-03 UTC; all counts drift.**
- **`NOASSERTION`** is GitHub's word for "a LICENSE file exists but does not match a known SPDX identifier". It is *not* permissive and *not* a licence name. It must be resolved by reading the file before any code is copied.
- **404 handling:** names that failed are stated explicitly rather than guessed at — see Missing evidence. `FlashGS/FlashGS`, `lkeab/VastGaussian`, `city-super/CityGaussian`, `city-super/CityGaussianV2`, `city-super/Urban-GS`, `city-super/Horizon-GS`, `autonomousvision/analytic-splatting`, `j-alexhuang/speedy-splat`, `valeoai/EAGLES`, `NVlabs/EAGLES`, `FlashGS/FlashGS`, `NVlabs/radsplat`, `google/neural-point-catacaustics` all returned 404; the correct live owner/name is used in the table where one was found.
- **Technical claims** marked as coming from a README were read from the raw README at the pinned default branch (Gaussian Point Splatting, StochasticSplats, splat-bvh-core, Spark, GaussianSplats3D, LoDOfGaussians, splat-transform) or from the project/official docs (PlayCanvas SOG + SuperSplat streaming). Numbers in those claims are **author-reported**, not independently benchmarked by this sweep.

## Contradictions

1. **"64-bit atomic visibility buffer" vs WGSL reality.** `docs/PAPER-SWEEP-2024+.md` entry #61 records `packDepthColor64` + `WGSL_GAUSSIAN_POINT_SPLATTING_SHADER` as an integrated "64-Bit Atomic Visibility Buffer" citing SIGGRAPH 2026. WGSL defines **no `u64` type**, and WebGPU exposes only the optional `atomic-vec2u-min-max` feature (`atomic<vec2<u32>>` with `atomicStoreMin`/`atomicStoreMax`), which is adapter-dependent and absent from the default feature set. Also, the Gaussian Point Splatting README never claims a 64-bit buffer — it says points are "splat[ted] … atomically" and lists 425M Gaussians / `--max-number-of-points 250e6`; the 64-bit framing appears to be our own design choice, not the paper's. **Interpretation (researcher inference):** either `pointSplatting.ts` implements something other than true 64-bit atomics, or the WebGPU path cannot currently run as documented. This needs a code audit before it is claimed in product material.
2. **StopThePop licence.** Inventory entry #51 records "MIT / GS-deriv"; the GitHub API returns `NOASSERTION` for `r4dl/StopThePop`. Unresolved — read `LICENSE.md` before reuse.
3. **Spark's API surface.** The Spark README describes WebGL2 targeting and a `THREE.WebGLRenderer` example, and no WebGPU support was found in that README; secondary commentary in this sweep's search results describes newer Spark versions as WebGPU-capable. Treated as README-only evidence (WebGL2) and flagged as possibly stale.
4. **Large-scene splat counts.** PlayCanvas documents enforced budgets of 2M/4M Gaussians on desktop, while Gaussian Point Splatting reports 425M interactive on an RTX 4070 Ti SUPER. Not a factual conflict — different renderers, different fidelity targets — but it means "100M+ " should never be quoted as a browser-wide claim; it is a hardware- and algorithm-specific figure.
5. **RadSplat "900+ FPS".** Author-reported on unstated hardware; also `m-niemeyer/radsplat` is a 5-star project page, not a code release, so the number cannot be reproduced from this repo.
